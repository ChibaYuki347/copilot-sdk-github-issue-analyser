## 概要

GitHub Issue Complexity Analyser は、GitHub Copilot SDK を使って GitHub Issue の複雑さを AI で評価します。この文書では、このツールに関する責任ある AI の考慮事項をまとめます。

## このツールが行うこと

- 公開されている GitHub Issue データ (`title`、`body`、`labels`、`comments`) を読みます
- 公開されているリポジトリ内容 (ファイル構造、ソースコード) を読みます
- 推奨される開発者のスキルレベルを含む複雑さ評価を生成します
- すべての出力を透明に提示します - ユーザーはすべてのツール呼び出しとデータソースを確認できます

## このツールが行わないこと

- 採用、解雇、またはパフォーマンス評価の判断は行いません
- 開発者に関する個人データを保存したり、プロファイリングしたりしません
- ユーザーが認証を提供しない限り、private repository にはアクセスしません
- Issue を自動で割り当てたり、リポジトリに対してアクションを実行したりしません
- 人間のエンジニアリング判断を置き換えません

## 主要な考慮事項

### 人間による監督

このツールが出すのは **推奨であり、決定ではありません**。どの評価も、実際に運用へ反映する前に、エンジニアリングマネージャーまたはテックリードが確認する必要があります。スキルレベルの推奨は議論の出発点であり、自動割り当てではありません。

### スキルレベルラベル

「Junior」「Mid-level」「Senior」「Senior+」というラベルは、**その開発者の年次や序列、全体的な能力や価値**ではなく、**特定のコードベースと関係技術への習熟度**を指します。ある領域ではシニアの開発者でも、別の領域ではジュニアになり得ます。したがって、これらのラベルを年功序列として解釈してはいけません。このツールは、門前払いのためではなく、開発者の成長を支援するために「メンタリングのヒント」を明示的に含めています。

### バイアスへの認識

- **Issue 品質バイアス** - 情報が少ない Issue や書き方が不十分な Issue は、実際より単純に見える可能性があります。詳細に文書化された Issue は、より複雑に見える可能性があります。結果を解釈するときは、この点をチームで意識する必要があります。
- **言語バイアス** - 英語以外の言語、または標準的でない用語で書かれた Issue は、評価精度が下がる可能性があります。
- **リポジトリバイアス** - エージェントはコード構造をヒューリスティックに探索します。慣習的でないプロジェクトレイアウトでは、探索が不完全になる可能性があります。

> 💡 **日本語版での補足**: 日本語の issue は英語よりも agent が誤解する可能性が高いため、本ワークショップでは Demo 2 で実演します。詳細は `step-by-step/script.ja.md` の Demo 2 を参照。

### 透明性

- CLI では、すべてのツール呼び出しが発生した時点で terminal に表示されます
- Web UI では、各ツール呼び出しが詳細付きの chat bubble として表示されます (どのファイル、どのパス、どの検索クエリか)
- 結論だけでなく、エージェントの完全な推論も出力に含まれます

### データプライバシー

- このツールは、すでに GitHub REST API 経由で利用可能なデータにのみアクセスします
- データは永続的に保存されません - 各解析はステートレスなリクエストです
- GitHub API の rate limit は尊重されます。認証済みトークンは rate limit を増やすためにのみ使われ、ユーザーがすでにアクセス権を持つ範囲を超えて private data にアクセスするためには使われません

### 制約

- 評価の品質は、Issue の説明品質とコードベース構造の品質に依存します
- proprietary framework やドメイン固有のパターンは、完全には理解できない場合があります
- 複雑な multi-repository または monorepo の Issue は、十分に捉えられない可能性があります
- このツールは、組織上の文脈 (チームの余力、ビジネス上の優先順位、締め切り) を理解しません

## 緩和策

1. **常に「推奨」であり「必須」ではない形で提示する** - UI と出力文言の両方で、すべての評価を提案として位置づけます
2. **メンタリングの道筋を含める** - すべての評価に、経験の浅い開発者向けのガイダンスを含め、成長を促進します
3. **判断過程を見せる** - ツール呼び出しを完全に可視化することで、ユーザーがエージェントの推論を評価できます
4. **自動アクションを行わない** - このツールは読み取り専用かつ情報提供用であり、リポジトリや割り当てを変更しません
